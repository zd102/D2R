# 帧率优化与复测

2026-09-11，Windows / Edge 无头浏览器，AMD Ryzen 5 3600X、Radeon RX 7800 XT，硬件加速开启。

游戏默认使用「自动 · 优先 60 帧」：在持续超出帧预算时逐级降低场景的内部渲染分辨率，进一步关闭泛光、动态阴影以减轻密集战斗的绘制负担，稳定后缓慢恢复。界面保持原分辨率；怪物数量、碰撞、技能判定和模型细节不变。设置中的「精细」「流畅」仍可手动选择。自动模式将初始像素量限制在 2560 × 1440 以内，避免高 DPI / 4K 一开始就分配过大的渲染目标。

## 实测结果

以下均为自动模式，同一台机器单独运行浏览器测试。最低平均 FPS 指这一组采样点中最慢的一段平均值；最长帧另列，避免隐藏瞬时掉帧。

| 覆盖 | 采样点 | 最低平均 FPS | 最差 P95 帧时间 | 最长帧 |
| --- | ---: | ---: | ---: | ---: |
| 1080p，营地 + 25 关 + 2 隐藏区域 | 81 | 59.62 | 16.8 ms | 33.6 ms |
| 圣骑士密集战斗，奶牛关 / 第 18 关 | 2 | 59.95 | 16.8 ms | 16.8 ms |
| 亚马逊密集战斗，同上 | 2 | 59.75 | 16.8 ms | 33.3 ms |
| 法师密集战斗，同上 | 2 | 59.95 | 16.9 ms | 17.3 ms |
| 4K，第 1 / 18 / 25 关与奶牛关 | 12 | 59.62 | 16.8 ms | 33.3 ms |
| 390 × 844、DPR 3，同上 | 12 | 59.62 | 16.9 ms | 33.2 ms |

手机尺寸测试使用本机桌面 GPU 模拟视口与 DPR，不等于在真实手机上的性能测量。总计 20,700 个采样帧中有 5 帧超过 18 ms；所有采样点通过下述稳定帧率门槛，但仍存在约 33 ms 的偶发长帧，不能称为每一帧都达到 60 FPS。

本次本地报告位于 `.verification/performance-20260910/`，包括 `all-scenes-1080p`、`stress-paladin`、`pooled-stress-amazon`、`pooled-stress-sorceress`、`4k`、`mobile`。基线使用 `baseline-clean`；其他中间分析目录仅用于定位瓶颈，不混入这张结果表。

## 实际瓶颈

- Cannon 原有扫描先过滤静态碰撞对，导致大量墙体之间无法提前结束扫描。改为先检查排序后的 AABB 区间，再筛选实际候选。
- 默认碰撞历史矩阵每次清空与墙体数量平方成正比的存储。改为只记录实际接触，以稳定的刚体 ID 避免移除怪物后错配。
- 游戏已有 60 Hz 固定时间步，原先每次又插值所有墙体的四元数。正常固定步现在直接推进物理；较大的显式模拟步仍保留分步处理。
- 怪物不透明表面按材质合批，相同怪物部件共享 GPU 几何。动画骨架继续驱动矩阵；颜色、受击自发光、隐藏、尸体和阴影分别保留。离开区域时释放合批纹理、缓冲区和材质。
- HUD 文字仅在数值改变时写入；掉落标签缓存尺寸，窗口尺寸、DPI 或字体就绪时重新测量。
- 光圈、掉落光柱及适用的透明特效以单遍绘制双面，减少重复提交和着色器切换。
- 怪物减速只计算需要的灵气数据，避免逐怪重算整张角色属性表；装备损坏和切换仍立即生效。重复召唤复用同类型模型，同时重新生成生命、持续时间和战斗快照，并使旧召唤状态失效。
- 投射物按外观复用模型和 GPU 缓冲，每类最多缓存 32 个空闲模型；再次发射时重置位置、方向、缩放、可见性及特效参数，离开区域释放空闲和飞行中的模型。弹幕的命中记录与伤害快照仍每次重新生成。

最初在 1920 × 1080 精细画质下，奶牛关只有约 3–4 FPS；密集战斗夹具（24 个激活怪物、40 件掉落物、连续法师技能）在仅修复第一处碰撞扫描后仍约 26 FPS。这两个问题分别涉及物理和绘制提交，不能仅靠降低分辨率解决。

## 测量方法

`tests/performance-browser.mjs` 在真实游戏循环里采样 `requestAnimationFrame`，保留物理、怪物 AI、界面和 WebGL 渲染，记录平均 FPS、P50 / P95 / P99 / 最长帧、超预算帧数、分阶段耗时、实际分辨率和地图种子。使用独立浏览器存档与固定随机序列。无敌状态只防止测试角色死亡；战斗压力模式还提高敌人生命以维持交战。

默认覆盖营地、25 个主线区域、奶牛关与超级暗黑破坏神区域。每个主线区域分别测入口、怪群和首领，共 81 个采样点。压力模式持续施法并检查实际施法次数与激活怪物数，避免把静止、未启动的战斗算作压力测试。

帧率检查以平均至少 59 FPS、P95 小于 18 毫秒为约 60 Hz 的稳定运行门槛，允许浏览器时间戳误差和少量系统调度抖动。报告保留所有长帧，不用百分位替代最差帧。区域生成、首次着色器编译的预热阶段不计入稳定运行采样；这些结果也不构成任意硬件、任意分辨率下每一帧至少 60 FPS 的保证。

## 重现

先启动开发服务，然后逐项运行，性能采样期间不要同时跑其他浏览器测试或构建：

```powershell
npm run dev
$env:OUTPUT_DIR = '.verification/performance-local'
$env:PERF_ASSERT = '1'
npm run test:performance
```

密集战斗可按职业重复，`HERO_CLASS` 支持 `paladin`、`amazon`、`sorceress`：

```powershell
$env:AREAS = 'cow,17'
$env:STRESS = '1'
$env:HERO_CLASS = 'sorceress'
$env:WARMUP = '240'
$env:FRAMES = '300'
$env:OUTPUT_DIR = '.verification/performance-stress'
npm run test:performance
```

其他参数：`BASE_URL`（默认 `http://127.0.0.1:5173`）、`WIDTH`、`HEIGHT`、`DPR`、`CPU_PROFILE=1`、`PROFILE_DRAWS=1`。性能门槛仅在 `PERF_ASSERT=1` 时启用，便于在不同硬件上先记录实测数据。输出目录保存 `results.json`；CPU 分析额外保存每个采样点的 `cpu-profile-N.json`，绘制分析还记录长帧前后的分阶段耗时。结束压力测试后清除 `STRESS`、`AREAS` 等环境变量，才能恢复默认全场景覆盖。

功能与外观检查：

```powershell
npm test
npm run build
npm run test:monster-batches
npm run test:maps
npm run test:scenery
npm run test:controls
npm run test:ui
npm run test:memory
```

合批外观测试对 28 种怪物体型、待机/攻击/尸体/隐藏四种状态作 112 组像素对照，包含阴影与受击闪光。物理测试与穷举 AABB 候选比较，另覆盖接触边界、休眠、过滤、移除刚体、碰撞历史和大量静态墙体；自动分辨率测试覆盖持续慢帧、单次长帧、恢复迟滞及高 DPI 像素预算。

本次验证：324 项单元测试、构建、112 组像素对照，以及地图、场景、操作、界面、特效、远程攻击、职业、内存、隐藏区域和掉落拾取浏览器回归全部通过。构建仍提示现有包体超过 500 kB，未导致构建失败。隐藏区域回归修正了未鉴定物品名称的旧断言；拾取回归补全地图夹具并固定地图随机种子，随后均重跑通过。验证产物单独存放，验证前记录的已有文件未被修改。
