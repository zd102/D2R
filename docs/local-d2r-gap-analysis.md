# 本地 D2R 项目与原作差距

状态快照与整理日期：2026-09-09。

**本文中的 D2R 始终指当前工作区的本地项目“黯蚀 II · ECLIPSE”。** 暴雪《暗黑破坏神 II：重制版》统一称为“官方重制版”，只作为必要的版本参照。

配套文档：[暗黑2耐玩性分析](diablo2-replayability.md)，解释原作各系统为何能够支持长期游玩，以及社区偏好的分歧。

## 阅读范围与判断标准

本文集中分析本地项目已有能力、与原作的差距、差距对玩法的影响、开发顺序及验收方式。已有实现依据为当前工作区文档和代码的静态检查，包含尚未提交的内容；本次文档拆分没有重新进行全面功能审计。

初版分析没有运行游戏、构建或测试，不把已有文档中的测试成绩当作全面审计结果。2026-09-09 的远程专项更新已补充实际实现与验证，范围见 [远程武器与技能](ranged-combat.md)；不代表其余差距逐项重新验收。优先级是设计建议，不是已经决定的开发排期。

核心判断：**当前最需要增加的是装备用途、战斗机制和长期目标之间的联系。** 基础跨角色物品流转已通过营地共享仓库接入；雇佣兵、职业外技能、加工配方及更完整的构筑仍需要继续扩展。

## 一、对照基线与改编边界

| 对照层次 | 在本文中的用途 | 判断方式 |
| --- | --- | --- |
| 经典 Diablo II | 理解职业、任务、探索和多人玩法的起点 | 不将 LoD 后加的系统误算为 Classic 内容 |
| 《毁灭之王》1.13/1.14 | 本地角色与装备系统的主要原作基线 | 检查技能、装备、佣兵、加工、特殊事件与角色流转是否形成完整玩法 |
| 官方重制版后续更新 | 技能、便利性与终局设计的扩展参照 | 恐怖地带等后续内容属于可选借鉴，不能说成 LoD 1.13 原本就有 |
| 本地 D2R 的主动改编 | 短关卡、连续时间战斗、手机操作和调整后的成长节奏 | 分别判断体验是否成立，不把与原作不同一律视为 bug |

例如，官方重制版 2.4 改变了圣光弹/天堂之拳对恶魔的适用范围及天堂之拳冷却；本地采用部分 LoD 行为时，应先确定目标版本，再判断是否需要调整。[2.4 正式补丁][O5] 恐怖地带与破免护符同样是后续加入的系统。[官方重制版系统说明][O8]

差距分类为“缺失”“部分实现”“主动改编”和“后续版本参照”。收藏记录、过滤器等也可以因本地需求而增加，但不必将其包装为经典原作的逐项复刻。关于无尽终局、独立护符背包或大幅提高掉率的取舍，见[暗黑2耐玩性分析](diablo2-replayability.md)。

应特别避免三种误读：

- 已有珠宝镶嵌，不代表宝石已经能镶嵌；宝石等杂物已有掉落、保存和出售，但缺少完整使用机制。

另有一些历史文档尚未同步所有后续变化。例如 `PALADIN.md` 的部分段落仍写 25 个符文之语或装备子集，而更新的目录与代码已扩展。审查应采用当前代码和专题文档，不能只凭某段旧说明判断缺失。

## 三、本地项目与原作的差距矩阵

“缺失”表示没有相应的完整玩家流程；“部分”表示已有实际实现但范围或规则不同；“改编”表示有意采用不同规则。三者都不自动等同于 bug。

| 领域 | 状态 | 具体差距 | 对体验的影响 | 建议优先级 |
| --- | --- | --- | --- | --- |
| 装备授予技能 | 部分 | 聚气、职业外技能和传送未接入 | 谜团、战争召唤等不能提供完整的标志能力 | 最高 |
| 固定装备变量 | 基础已实现 | 暗金/套装生成、符文之语制作时按原区间随机，孔数可变，保存和导入保留原值；图鉴使用稳定示例 | 重复掉落与重做配方已有变量追求，最佳版本比较仍可增强 | 随机已完成，比较功能中 |
| 远程武器 | 基础已实现/改编 | 已补齐弓弩/投掷飞行、命中、弹药、穿透、魔法箭/爆炸箭及模型；原版箭筒槽、逐职业帧表与其他职业远程技能仍缺少 | 基础远程装备已有实际用途，更深的远程构筑依赖职业与技能扩展 | 基础已完成，扩展中高 |

| 佣兵 | 缺失 | 无雇佣、装备、灵气支援、复活和独立成长流程 | 缺少第二套配装及大量装备的使用者 | 最高 |

| 精英怪 | 部分 | 主要为固定倍率强化，缺少完整随机词缀组与随从组织 | 同一地图重复遭遇差异较少 | 高 |
| 区域地图 | 改编 | 固定关卡布局，缺少原作区域网络与地图种子流程 | 探索、找路和刷取路径变化有限 | 高 |

| 收藏记录 | 缺失 | 百科可查全部物品，但不是实际发现记录 | 收藏目标缺少可见进展 | 高且适合先做 |
| 地面过滤 | 未见完整流程 | 百科搜索不能替代掉落标签过滤 | 大掉落池提高视觉与拾取负担 | 中高 |

| PvP 与天梯 | 缺失 | 无敌对、对局、可信排名与赛季迁移 | 竞技、低等级装备需求和经济重启缺失 | 后期独立方向 |
| 视听世界 | 部分 | 已有场景与模型；音频入口是少量振荡器合成提示 | 物种、材质、环境与章节声音辨识尚有扩展空间 | 高，需实机评估 |
| 规则档位与平衡 | 改编 | 连续时间战斗、简化武器系数、放宽耗蓝与后期经验 | 原作攻略与本地实际可能出现偏差 | 持续校准 |

以上依据主要为[装备属性边界](item-attributes.md)、[目录适配](item-catalog.md)、[地图规则](maps-chests.md)、[平衡说明](balance.md)和当前源码。优先级指对玩法的贡献，不是对工作量的排序。

### 3.1 差距最大的是“能力存在”，不是“名称存在”

在 `item-catalog.ts` 中，原始属性状态明确区分 `active`、`other-class`、`inactive` 和 `unused`；`charged`、`oskill`、`ethereal` 等在未接入说明中可见。这里已经有诚实标注，但下一步仍需要让关键能力真正工作。

远程专项完成后的专题统计有 241 条原始属性记录未接入、189 条属于其他职业，另有禁用和外观标记。不能把记录数直接算成“复刻完成百分比”：缺一条传送和缺一条低影响属性，对玩法的影响完全不同。

因此应该按物品的核心能力排优先级，先定义要支持哪些实际构筑，再补齐它们依赖的机制。把几百项转换映射都实现之后仍没有使用场景，也不是一个好的阶段目标。

### 3.2 固定装备随机变量已接入

初版检查时固定装备复制中间档模板。2026-09-09 已改为在暗金/套装生成及符文之语制作完成时逐件掷值；可变孔数也参与随机。`catalogMods()` 的默认中间档只用于模板、稳定预览及历史兼容，运行时生成显式传入随机源。

新物品记录真实变量，鉴定、保存、导入和读取不会重新掷值；旧目录装备数值保留，随机刻面在镶嵌后也不会被迁移覆盖。全部 584 个条目的边界与持久化测试见 [随机变量说明](item-rolls.md)。

重复暗金与重复配方已经可以比较变量，也可通过营地共享仓库交给其他本地角色；后续仍应配合收藏和材料消耗，避免仓库快速被低价值重复物品占满。

### 3.3 多职业与掉落池必须共同设计

`HeroState.classId` 当前固定为 `'paladin'`，而装备数据已经包含其他职业的专属类型。这种配置会让玩家捡到有身份、但无法实际尝试的装备。

三种可行方向是：按明确节奏实现其他职业；给不可用职业物品建立有限的收藏或兑换价值；在单职业模式下调整掉落池。最后两种属于本地改编，应明确说明，而不是悄悄把全职业掉落都改成圣骑士属性。

长期最接近原作的方向是多职业加共享仓库。短期最可控的是先加入一个能显著复用现有系统、又提供不同战斗节奏的职业，而不是同时宣布补齐全部职业。

### 3.4 地图要增加决策，而不只是面积

`makeLevelLayout()` 由关卡序号和地形构建固定路线，`levelLayout()` 按关卡缓存；世界中的随机装饰也不能等同于随机区域拓扑。

当前 81×81、分支和环路已提供基础空间。下一步更有价值的是出口位置、精英组合、可选支线、地形瓶颈与特殊奖励之间的变化。单纯把网格继续放大，可能只增加走路时间。

也可以保留固定图作为练习和速刷选项，另增可复现种子的远征。两类体验不冲突，且有助于将探索和效率目标分开平衡。

### 3.5 精英需要改变战术

目前额外精英主要使用更高生命、伤害、防御和移动倍率，并继承物种招式。建议从少量可读、可组合的机制开始，例如防御强化、远程支援、元素增幅、护卫协同和可规避的死亡效果。

不应直接照抄所有历史上的极端组合。词缀之间必须有冲突约束和难度预算，保证玩家可以从名称、外观和行为判断风险。新增精英的验收重点应该是“玩家需要更换集火或站位”，而不是击杀时间被机械拉长。

### 3.6 特殊护符需要匹配获取过程

当前地狱迪亚波罗和巴尔各有额外 0.5% 对应特殊护符掉落，是项目为缺少超级事件采用的替代规则。[具体说明](item-catalog.md)

这种适配让奖励可以获得，却让玩家不必构建专用挑战角色。后续若新增超级事件，要同时决定旧掉落是否保留、新入口材料从何而来、旧存档装备如何对待，以及专用挑战是否仍值得参与。

不能仅补一个“超级首领”按钮而保留所有最优获取都在普通流程；奖励和挑战需要形成合理对应。

### 3.7 音效与氛围需要独立预算

`audio.ts` 当前为命中、挥击、施法、掉落、升级、受伤和传送等事件生成简短信号。静态代码并不能证明这些声音实听不好，但它表明目前没有在该入口呈现完整的章节音乐、环境声、物种音色与装备材质层次。

原作的长期记忆不仅来自打击声，也来自“城镇安全”“地下危险”“远处出现某类怪物”的预期。建议把环境声、怪物提示、稀有掉落辨识和近战反馈列入核心体验预算，而不是全部推迟到内容完成以后。

## 四、建议的开发顺序

开发范围需要区分长期单人体验与包含多人、交易和赛季经济的完整体验，两者所需工作量相差很大。以下以“优先完成耐玩的单人体验，保留多人扩展可能性”为建议基线，不代表用户已决定放弃其他方向。

### 阶段 0：明确规则承诺

建立一张按版本划分的机制清单：采用 LoD 规则、采用 官方重制版 调整、项目主动改编、尚未支持。图鉴应展示玩家在当前规则下实际能够使用的效果。

尤其需要决定圣骑士技能、经验、掉率、药水、尸体、地图和特殊护符的规则基线。若没有这一步，后续会在“忠于原作”和“改善本地短关卡节奏”之间反复冲突。

不需要先重写所有已有系统；需要先让每项实现有清楚的验收依据。

### 阶段 1：让现有掉落持续有用途

建议按可以独立验收的组合交付：

1. **共享仓库已完成基础，真实发现记录待做。** 营地已接入背包/个人仓库与共享仓库的四个直接转移方向，支持事务保存和旧窗口保护；详见 [共享仓库](shared-stash.md)。
2. **固定装备实际掷值：已完成。** 掉落和制作时记录变量，存档稳定保留；下一步可增加已拥有最好版本的比较界面。
3. **宝石与方块的首批完整配方。** 至少覆盖镶嵌、升阶、基础重掷、打孔或清孔中的一个自洽集合，建立材料获取与消耗。
4. **一类完整佣兵。** 推荐先验证能与圣骑士配装产生明确互补的一类，包括装备、灵气、治疗、复活和跨地图。
5. **无形及若干关键装备能力。** 与佣兵一起建立底材用途；按实际构筑补齐传送、聚气或其他授予技能。
6. **远程武器的真实控制：基础已完成。** 投射物、命中、弹药、穿透、特殊箭和模型已接入，并优化圣骑士远程技能。后续按职业扩展导引、齐射、元素标枪等机制，原作帧表和箭筒管理按项目定位取舍。

这里的第 4 至第 6 项明显比“添加数据”更复杂，可以拆分里程碑。不能将它们一概称为容易实现的生活质量功能。

阶段完成的标志：同一轮掉落里，有物品能立即穿，有物品给佣兵，有物品留给小号，有材料能继续加工，重复暗金仍值得看一眼。

### 阶段 2：给不同构筑不同目的地

优先补三类明显不同的刷取场景：适合范围清怪的高密度区域；适合低成本寻宝的短路线；适合专门配置的高风险首领链。再增加有限精英词缀与可复现地图变化。

可以从牛场式密度区域、钥匙至超级首领流程，以及已有五章中的可选特殊区域开始。恐怖地带式轮换可以后接，避免在基础区域本身仍很相似时仅给它们加等级。

阶段完成的标志：玩家会因当前目标和配装而主动选择至少几条不同路线，不再只是永远进入最高解锁关卡。

### 阶段 3：增加另一种完整角色体验

优先选择第二职业时，需要比较真实依赖：

| 候选方向 | 可复用基础 | 新增难点 | 对装备池的帮助 |
| --- | --- | --- | --- |
| 法师 | 现有法术投射物、元素伤害和状态 | 传送、多种施法形态、法力与免疫路线平衡 | 激活法杖、法球、法系装备和大量跨职业用途 |
| 死灵法师 | 已有诅咒和部分友方单位逻辑 | 多召唤寻路、尸体所有权、尸爆与召唤存续 | 激活死灵专属装备，显著扩大尸体系统用途 |
| 野蛮人 | 现有近战与武器系统 | 真正双持、旋风/狂乱、战吼、寻找物品 | 扩大武器、金币与尸体再次掉落的价值 |

选择哪一个取决于希望先提供的体验和完成质量，不能只按“数据容易复制”排序。正式加入前，需要完成初期、过渡和终局三段成长，不能只在满级测试房间里看起来可用。

阶段完成的标志：玩家使用两个职业时，技能节奏、刷图选择和想保留的装备都明显不同。

### 阶段 4：世界体验与高重玩目标

在已有骨架上逐步增加区域连接、独特任务服务、更多城镇身份、环境音和怪物反馈；加入可选专家模式、个人挑战、收藏里程碑和稳定的速通记录。

其中声音、操作和存档可靠性应在前几个阶段持续改善，不必等到阶段 4 才开始。本阶段的重点是把这些能力组织成更完整的旅行和长期成长体验。

### 阶段 5：多人作为独立工程目标

若需要联机，首先完成小规模合作的完整流程：创建/加入、同步移动与战斗、同一掉落只属于一个确定结果、任务共享、角色离线和重连、存档恢复。之后再考虑交易、天梯、敌对和 PvP。

当前角色保存在浏览器 `localStorage`，并支持 JSON 导入。这非常适合单人和用户自主保存，但如果未来引入公开经济或可信排名，就必须区分本地自由角色与服务端验证角色。

必要能力包括服务端权威结算、角色和物品身份、交易原子性、重复请求处理、掉线恢复、版本协议与数据迁移。否则增加一个“交易”界面也不能提供可靠的经济系统。

这里不是要求先建设大型线上平台。先证明少量玩家能够稳定合作，再决定是否承担公共市场与赛季运营，才容易控制范围。

## 五、用实际玩家流程验收，而不是用条目数验收

下面是建议的验收场景，并非本次已经执行的测试。

| 场景 | 能证明什么 | 不能只检查什么 |
| --- | --- | --- |
| 角色 A 拾取物品，存入共享仓库，角色 B 取出并使用，重载后仍正确 | 跨角色装备流转真实可用 | 仅存在“共享”标签 |
| 同一暗金多次掉落有合法变量，重载/导入后保持原掷值 | 极品追求与存档一致性 | 每次查看随机变动 |
| 捡到无形武器，给佣兵使用并跨关/复活 | 无形限制和佣兵价值形成联系 | 只显示半透明外观 |
| 装备授予传送后可施放，脱下后失效，快捷键和法力规则正确 | 装备实际改变通行能力 | 面板存在“传送”字样 |
| 弓箭命中远处目标，受墙体/弹药/穿透规则影响 | 远程战斗成立 | 近战扣血配一个箭头特效 |
| 材料通过方块消费，结果合法，失败操作不丢物 | 加工循环可用 | 配方列表可查 |
| 普通装备角色能稳定获得一次中期提升 | 成长入口成立 | 只验证满配角色伤害 |
| 热诚、锤子和专用首领配装分别在适合场景有价值 | 构筑与目的地存在差异 | 只在单个无障碍首领上比较 DPS |
| 专家角色死亡后无法继续推进，存档重载不恢复生存状态 | 专家规则一致 | 只增加死亡提示 |
| 发现记录区分首次、重复、版本和导入来源 | 收藏目标可信且可理解 | 百科条目全亮 |
| 随机地图可从入口到任务和出口，精英组合可读且可应对 | 探索变化不会破坏可玩性 | 随机数种子发生变化 |
| 两人同时拾取/交易同一物品后结果唯一，断线后可恢复 | 多人数据有可信规则 | 两个浏览器看到同一场景 |

测试风险也要与功能匹配：共享仓库、随机变量和交易必须重点检查保存与原子操作；地图要检查可达性；战斗要检查技能实际结算；音效和操作则需要真人体验。纯数值回归不能替代后几类验证。

## 六、如何判断新增内容有没有提高耐玩性

不建议用“地图数量”“暗金数量”或一个综合复刻百分比来代替体验评价。更有用的观察是：

| 指标 | 观察方式 | 判断意义 |
| --- | --- | --- |
| 有效战利品比例 | 记录捡到后穿戴、转交、加工、收藏、出售的用途 | 是否大量物品只有无意义处理成本 |
| 无进展时间分布 | 看不同玩家多久没有装备、材料、收藏或能力进展 | 随机长尾是否挤走普通玩家 |
| 刷取路线分布 | 按构筑、装备档次和目标分别统计 | 是否只有一个地点在所有情境最优 |
| 构筑分布 | 区分开荒、成型、首领、清图与挑战 | 冷门技能是否有实际场景 |
| 第二角色建立率 | 观察掉落是否促使尝试其他玩法 | 跨角色循环是否成立 |
| 重复物品保留原因 | 变量、佣兵、小号、收藏或加工 | 是否有超出首次获得的价值 |
| 材料收支 | 获取量、消耗量和库存变化 | 方块与打造是否真的消耗材料 |
| 城镇和整理时间 | 与战斗、探索时间比较 | 游戏时间是否被操作事务占据 |
| 死亡原因与可解释性 | 结合战斗记录和玩家描述 | 是合理风险还是难以理解的失败 |
| 自愿回归理由 | 询问下一次想完成什么 | 是否拥有玩家自己认可的下一目标 |

若没有遥测，也能通过少量结构化试玩记录完成初步判断。不要凭一次熟练开发者的通关时间估计所有玩家，也不要只追求延长在线时长。

特别建议区分至少三组试玩：不了解暗黑2的新玩家；熟悉暗黑2但使用本地普通掉落的玩家；以合法中高端配装评估终局的玩家。这三组回答的是不同问题。

## 七、产品方向上的最终判断

对本地 D2R，已有的圣骑士、装备库、短战役、掉落与百科提供了可继续扩展的基础。当前最强的开发组合是：**关键装备能力真正生效、共享仓库与发现记录、佣兵和无形、方块加工，以及有不同定位的刷取和挑战区域。** 随后再用第二职业放大战利品的用途。

项目可以保留便捷拾取、短关卡、手机操作和较快升级等改编。是否接近暗黑2的长期乐趣，应看玩家能否从一次掉落开始，继续规划装备、选择路线、解决新挑战、帮助另一个角色并记住这段经历，而不是看每一项旧操作是否原样照搬。
