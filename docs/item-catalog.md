## 核对口径与数量

以上为完整导入目录及存档兼容口径。当前获取池已排除未开放职业的 66 个专属底材、15 件暗金、4 件套装和爪专用「沌顿」配方，实际可获取为 434 个底材条目、364 件暗金、123 件套装和 83 个符文之语；全部 33 枚符文保留。箱子无功能杂物及无属性白色首饰也已退出获取，详见 [当前物品获取范围](item-availability.md)。

不进入随机装备池的六件任务暗金是蝮蛇护符、国王之杖、赫拉迪克法杖、地狱熔炉之锤、克林姆连枷及克林姆的意志。它们对应现有任务流程，不作为随机装备重复掉落。未启用的测试物品、六种投掷药剂、宝石、箭矢、卷轴与其他消耗品不计入装备目录。蓝黄装备与打造物品是规则生成的组合，不是可逐件穷举的固定名称目录；打造系统仍未实现。

## 数据来源

- 底材、暗金、套装、套装加成、符文之语和符文宝藏表来自固定的 [LoD 1.13 原始数据提交](https://github.com/fabd/diablo2/tree/e67aa992be5db412bd0437bb8afb95eedee0c9bc/code/d2_113_data)。
- 名称参考固定的 [D2R 中文字符串表](https://github.com/blizzhackers/d2data/blob/fc469993502d0498809b9fc1af140ee2a9eb8902/json/localestrings-chi.json)，转换为简体；仅使用名称，不引入该版本的装备数值。保留现有物品名称；不同底材的中文名碰撞时附上英文底材名。
- 重建数据：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/import-items.ps1`。导入器使用 TSV/JSON 解析器，过滤无效记录，保留稳定 ID、原始属性、权重及等级，生成 `src/item-catalog-data.ts`。游戏运行时无外网依赖。
- 规则核对：[官方暗金物品](https://classic.battle.net/diablo2exp/items/uniques.shtml)、[MF 规则](https://classic.battle.net/diablo2exp/items/magic/magicfind.shtml)、[符文稀有度](https://classic.battle.net/diablo2exp/items/runes.shtml)、[地狱熔炉奖励](https://classic.battle.net/diablo2exp/quests/rewards.shtml)。

## 生成规则

暗金/套装使用独立的质量等级 qlvl 和底材宝藏等级 TC 校验，装备需求等级只控制穿戴。例如乔丹之石需求等级 29，qlvl 为 39，不能再从等级 29 的掉落池中抽出。原始同类暗金权重保留，例如拿各 15、玛那得 15、乔丹 1；原始权重用于本项目候选池中的相对抽取，不能直接解释为每次击杀的掉率。

普通底材也按原始 qlvl 筛选，不让历史简化底材等级提前开放高阶装备。新生成装备统一使用原始需求、类别和武器基础伤害；历史名称和占格兼容保留。所有新增底材接入原有蓝黄词缀筛选。圣骑士、亚马逊、法师的专属底材保留掉落，仅对应职业可穿戴；未开放职业的专属底材不再掉落。

符文之语检查原始物品类型继承、允许类型、排除类型、准确孔数及顺序。所有配方均把符文本身效果和原表配方效果各结算一次。完整符文之语不会直接掉落，需要制作。

套装有独立归属，按不同部件计数；支持现有属性系统可结算的整套/部分套装加成，以及 `add func=2` 的单件随件数奖励，西刚也统一使用原表。珠宝可以从背包或仓库镶嵌，消耗一个孔并保留属性，已镶珠宝的普通物品不能再组成符文之语；暗金护身符放在背包中、已鉴定且等级满足时生效，同一暗金护身符的多份副本不叠加。

## 25 个首领

`src/boss-loot.ts` 为每个守关首领定义偏好部位、重点暗金、额外暗金概率、额外符文概率和三难度 TC 上限。额外暗金只从等级/TC 合法且匹配部位或重点物品的候选池中抽取，重点物品相对权重乘 4。这是项目新增的定向刷取规则，原版并没有这些通用的个人专属暗金表。

| 来源 | 额外暗金概率，0 MF | 额外符文判定 |
| --- | --- | --- |
| 第一至第五幕守关首领 | 6% / 7% / 8% / 9% / 10% | 8% |
| 第一至第五幕章节首领 | 20% / 22.5% / 25% / 27.5% / 30% | 12% / 14% / 16% / 18% / 20% |
| 崔凡克议会首领 | 使用所在幕守关概率 | 25% |

以上判定附加在已有掉落上。普通怪物原有装备/符文/护符概率仍为 16%/3.5%/0.6%；小首领为 80%/28%/2.5%；章节首领保留两件基础装备、70% 基础符文和首通第一件暗金/一枚符文保底，另有 4% 魔法护符判定。因此章节首领现在可能掉落超过两件装备。

## 特殊符文与护符

- 通用符文保留现有区域/难度上限，实际相对概率改用原始 `Runes 1` 至 `Runes 17` 的递归权重。例如最高符文宝藏表中 Zod 的条件概率为 `1/5171`，还要乘以本项目进入符文判定的概率，不能当成每次击杀概率。高难度和首领不再额外乘虚构的高符文权重。
- 女伯爵在基础 28% 符文之外，使用原始 `Countess Rune` 的 3 次独立判定，每次 75% 成功。专用池普通最高 Ral、噩梦最高 Io、地狱最高 Ist；基础符文池独立，地狱基础池仍有更罕见的高阶符文。一次击杀合计 0–4 枚，取消旧的固定 2–3 枚。未模拟原版装备与符文共同竞争六个掉落位置的完整逻辑。
- 火焰之河首领首通额外掉 1 枚熔炉符文：普通 El–Amn、噩梦 Sol–Um、地狱 Hel–Gul，各自 11 枚等概率。随难度通关记录保存，重刷不重复发放。
- 地狱迪亚波罗额外 0.5% 掉毁灭小护身符；地狱巴尔额外 0.5% 掉地狱火炬。两者不进入普通暗金池。这是为没有超级首领事件的当前战役增加的获取途径，**不是原作普通迪亚波罗/巴尔的掉落规则**。
- MF 使用原有暗金递减收益 `MF * 250 / (MF + 250)`；额外暗金单次判定最多 75%。MF 不改变符文数量、种类、熔炉范围或特殊护符概率。随机流程先处理符文和金币，再处理装备品质，避免品质分支消耗随机数而影响本次符文结果。

## 适配边界与验证

“完整目录”指条目和生成入口齐全，并非所有原版装备机制都已复刻。暗金、套装及符文之语的有效变量已在生成/制作时按原始区间随机，可变孔数也参与掷值；旧物品数值保留，详见 [随机变量](item-rolls.md)。元素增伤/减抗、吸收、装备灵气、自动修复及部分装备诅咒已接入。聚气、传送、其他触发法术、特殊 `add func=1` 套装条件、无形等仍未实现，图鉴会标出未生效项。弓弩/投掷已支持真实投射物、弹药、穿透和特殊箭属性，规则见 [远程说明](ranged-combat.md)。完整边界、数据修正和存档迁移见 [装备属性核对](item-attributes.md)。火炬技能奖励适配为圣骑士 +3 技能。

`tests/catalog-loot.test.ts` 核对全部目录 ID、每件暗金/套装存档往返、全部 75 种首领/难度组合、qlvl/TC 门槛、符文递归概率、MF 与符文独立性、女伯爵和熔炉边界、普通怪物隔离、珠宝孔数和暗金护符去重。原有测试继续覆盖全部 78 个配方可制作性和蓝黄装备规则。

`BASE_URL=http://127.0.0.1:5175 node tests/catalog-loot-browser.mjs`（PowerShell 先设置 `$env:BASE_URL`）验证桌面/手机端首领提示、78 个配方、珠宝镶嵌、重载存档、非空 3D 画面及真实战斗掉落调用。完整单元测试用 `npm test`，构建用 `npm run build`。
