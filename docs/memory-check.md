# 浏览器内存检查

检查日期：2026-09-10。环境为 Windows、Edge 无头浏览器、1280 × 800、高画质。使用独立页面和测试角色，未访问玩家已有存档。

## 发现及修复

任务完成时，`GameWorld.completeObjective` 创建新材质覆盖指示环的旧材质，旧材质没有通知渲染器释放着色器引用。反复完成任务并返回营地后，`renderer.info.programs` 的使用计数总和持续增长；本次改为更新原有材质的颜色和透明度。

自动修复进度使用以物品 ID 为键的 `Map`，已丢弃装备的 ID 在离开场景前不会删除。改为以物品对象为键的 `WeakMap`，使记录随物品回收；同一件装备暂时卸下再穿回仍保留小数进度。

场景销毁另补充实例化网格自身缓冲区及完整阴影渲染目标的释放。当前场景未调用旧植被生成方法，实例属性和第二阴影目标通过资源生命周期单元测试验证，未将其列为实际游玩中已经复现的泄漏。

## 浏览器复测

主循环检测用时 183.4 秒，战斗使用固定时间步加速推进，并实际提交 WebGL 绘制；这不是连续数小时的实机游玩记录。每轮操作结束后等待临时提示等回调完成，再通过 CDP 触发垃圾回收，比较相同场景的保留内存、DOM、监听器及图形资源。

- 60 次职业模型切换。
- 12 次百科打开/关闭、72 次怪物模型选择。
- 五幕各重复 5 次进入关卡、完成任务指示及返回营地，共 25 次往返。
- 背包、角色、技能、地图、任务、暂停面板共 240 次打开/关闭。
- 32 次真实鼠标拖拽及取消，检查临时 DOM 和动画回调清理。
- 1,000 件自动修复装备轮换。
- 三职业共 240 次普攻/技能释放请求，包括投射物、范围场、女武神、诱饵和多头火蛇；推进约 12.4 分钟的游戏时间并等待效果结束。
- 20 波敌方弹幕/范围攻击，60 个临时敌人，检查死亡后的模型、施法状态及投射物清理。
- 独立音频检测连续播放 400 次音效。

| 修复后：普通面板 JS 堆 | 17.96 → 17.98 MiB | 稳定 |

| 音频：每批音效完成并回收后的节点 | 始终 1 个 AudioDestination | 无遗留音源或增益节点 |

战斗效果结束后的投射物、范围场、玩家召唤物和临时敌人集合均归零；百科关闭后仅保留主游戏的一个活动 WebGL 上下文。检测未发现这些操作引起持续增长的 JS 堆、DOM 或图形资源数量。资源修复、修复进度连续性及其他逻辑共 264 项单元测试通过，TypeScript 检查和生产构建通过。

这里的 JS 堆大小不等于浏览器进程总占用或显存。纹理、渲染目标、原生内存、图标缓存和编译缓存会产生合理的基础占用；图形计数表示显式创建/释放的资源数量，不表示显存字节数。首次进入新功能后的一次性增长和瞬时分配峰值不作为泄漏结论，仍需在实际设备上观察更长时间的游玩。

## 重现

在源码保持不变的独立开发服务上运行，避免 Vite 热更新刷新被测页面：

```powershell
npm run dev
npm run test:memory
```

可用 `BASE_URL` 指定测试服务，用 `OUTPUT_DIR` 指定报告目录。默认输出为 `.verification/memory-check` 和 `.verification/audio-memory`；`MEMORY_RECORD_ONLY=1` 仅记录趋势，正常回归不要设置此变量。测试通过 CDP 回收 JavaScript 对象，以弱引用跟踪 WebGL 句柄，避免检测代码自身保留资源。

相关代码与测试：`src/world.ts`、`src/combat.ts`、`tests/world-lifecycle.test.ts`、`tests/combat.test.ts`、`tests/memory-browser.mjs`、`tests/audio-memory-browser.mjs`。
