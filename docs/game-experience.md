# 游戏体验分析与优化

2026-09-29。分析以本项目现有实现、Windows / Edge 浏览器实测与自动化回归为依据，覆盖桌面鼠标键盘、手机竖屏与横屏。没有玩家留存或满意度数据，以下优先级依据可复现的操作障碍与实现成本。

## 多维度结论

| 维度 | 发现与影响 | 级别 | 本次处理 |
| --- | --- | --- | --- |
| 入门与目标引导 | 营地隐藏任务卡，玩家需要自行判断哪个传送阵用于推进战役；手机竖屏只显示任务名，进度需要打开面板 | 警告 | 营地显示“选择关卡出发”，点击后沿用原有走近传送阵的流程；有返程记录时显示“继续上次关卡”；竖屏直接显示任务进度 |
| 战斗可读性 | 技能栏主要用褪色提示资源不足，触屏难以查看原因；祈祷按持续耗蓝误显示为无法切换 | 警告 | 缺蓝和聚气耗尽同时提供文字标记、悬浮说明与无障碍名称；显示实际法力消耗或聚气剩余；零法力仍可切换灵气 |
| 战利品辨认 | 地面标签按掉落先后排版，普通装备可能先占满空间，后掉落的暗金或符文反而被隐藏 | 警告 | 任务物品、符文与高品质装备优先占位；增加可逆的精选显示，保留临时查看全部和明确的状态按钮 |
| 操作连续性 | 已有连续施法、短时间输入缓冲、WASD / 鼠标模式和失焦暂停 | 已具备 | 新提示不禁用技能按钮，不改变攻击节奏和输入缓冲；切换窗口时清除 Alt 临时显示状态 |
| 移动端与无障碍 | 桌面快捷键无法单独满足触屏；增加按钮可能挤占摇杆或技能区 | 警告 | 掉落切换按钮至少 44px，触屏可直接操作；提示同时使用文字与颜色；窄横屏继续压缩任务卡，保留主要战斗空间 |
| 性能 | 静止状态下，药水、状态标题和头顶资源条每帧重复写入相同属性；每个技能还重复计算装备技能加成 | 警告 | 属性、样式和隐藏状态按需更新；技能栏复用当前帧已计算的装备属性；聚气数量变化只更新文字，避免重建图标 |
| 成长与构筑 | 已有三难度、七职业、分阶段平衡审计和人数难度说明；本次没有玩家卡关分布或装备淘汰率证据 | 机会 | 维持现有成长、掉率与经济规则。后续先采样首个技能解锁时间、首关死亡原因与背包整理耗时，再决定数值调整 |
| 存档与可靠性 | 显示偏好不应改变角色进度，也不能因存储失败中断游玩 | 已具备 / 加固 | 新偏好独立存于当前浏览器；旧用户默认全部显示；写入失败保留本次切换并提示，角色存档格式不变 |

## 使用方式

- **掉落标签**：设置 → 掉落标签，或战斗地图下方“掉落”按钮。桌面按 **L** 切换，按住 **Alt** 临时显示全部，松开即恢复。
- **精选保留**：全部符文、任务物品、稀有 / 套装 / 暗金 / 符文之语 / 传承装备、护符、珠宝，以及有孔、无形、超强、带技能或职业固有词条的底材。其余普通和魔法装备标签隐藏。过滤只控制标签，不删除物品，不改变模型、掉落概率、自动拾取补给或背包内容。
- **密集掉落**：重要物品优先排版，同优先级保持掉落顺序。屏幕空间不足时仍可能隐藏部分标签；当前正在走近拾取的物品不会因切换精选而失去标签。
- **技能提示**：按钮上的“缺蓝”“耗尽”在资源恢复后自动消失。鼠标悬浮或键盘聚焦可查看消耗；技能仍可点击，以保留现有提示与输入缓冲。灵气提示说明的是切换消耗，不代表持续生效没有资源成本。
- **营地目标**：鼠标 / 触屏点击目标卡可走向传送阵；WASD 模式按现有规则先靠近，再按 F 或点击交互按钮。返程卡使用保留的远征记录，不重新生成当前关卡。

偏好在本地与在线模式下均按当前浏览器保存，不上传账号。游戏区域和控件继续沿用现有视觉样式。

## 性能证据与边界

修改前，在 1440 × 900 的营地冻结模拟，仅重复执行 60 次 `ui.update(0)`，观察 HUD 与世界标签的属性 / 节点变化，共有 **1,320 次重复写入**，其中药水提示、隐藏状态、跑步按钮和头顶资源条占主要部分。

使用同一初始角色和相同观察范围复测，结果为 **0 次写入**。新增回归还在 1440 × 900、390 × 844、844 × 390 下检查 HUD 与角色头顶资源条，同样保持状态不变并连续更新 60 次，结果均为 **0 次写入**。该指标证明消除了这些控件的无效更新，不能直接换算为整局帧率提升；移动、战斗计时及资源变化仍会正常更新界面。

构建仍提示大于 500 kB 的 JavaScript 分块。百科、物品目录与游戏主模块的拆分可以作为下一阶段加载优化，需要另行测量首次进入和缓存命中耗时，本次不把构建警告解释成运行失败。

## 验证与实现

- `npm test`：616 项通过，含掉落过滤保护、优先级、装备技能加成、法力边界、灵气切换及聚气耗尽测试。
- `npm run build`：TypeScript 检查、原生音频完整性与生产打包。
- `npm run test:experience`：三种窗口下的营地入口、资源提示、过滤切换、Alt 释放、失焦恢复、真实拾取、密集掉落优先级、偏好持久化和稳定 HUD 检查。
- 原有 `npm run test:ui` 覆盖 166 个布局场景；`npm run test:mobile-ui` 覆盖 8 种手机尺寸与 80 个面板。`npm run test:controls`、掉落拾取和返程回归检查已有行为，返程测试也覆盖新的目标卡入口。

同时校正了旧回归脚本的前置条件：切换场景和刷新前等待异步存档完成；药水栏按四个槽位计数；近距离攻击场景放在无遮挡空地；WebGL 画布在渲染帧内采样，避免读取已被清空的绘图缓冲。
