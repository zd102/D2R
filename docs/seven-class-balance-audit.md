# 七职业主要流派分阶段强度审计（2026-09-15）

审计游戏版本：`faea7c26c33f5706dfcf8da16505c39c7c4164ea`。这是本项目现有 3D 战斗实现的检查，不是原作职业排名。覆盖七职业的 37 种主要构筑；不同装备触发组合、全部双修比例及极限毕业配装不在本轮穷举范围内。

## 条件与结论边界

- 主线单人 1PP，清约 65% 的怪、不刷牛场。`simulateProgression(.65)` 得到普通／噩梦／地狱通关等级为 **36／65／86**；另检查 6、12、26、47、75 级的过渡阶段。
- 技能前置、每级可投入上限、任务技能点、属性点、装备需求、底材出现等级和底材最大孔数均检查。每个阶段可重新分配技能，符合项目解锁后的无限洗点规则。尚未解锁核心技能时，表中记录的是前置技能的过渡玩法。
- 装备采用可装备的中档参考预算：钢铁、精神、和谐、荣耀、知识、隐密、烟雾，后期单手近战使用非无形誓约；稀有物品最多四条现有合法词缀，取中位变量。**定向选择的配装不是掉落概率模拟，也不保证玩家到达该关时已经凑齐。** 双手武器／双爪会失去盾牌抗性，实际法力、抗性、词缀和加点见数据文件。
- 主表不带佣兵，以显示角色本身的输出与防护。另有同等级眼光力量佣兵对照、装备不足、压碎性打击装备、白色魔杖、马赛克及召唤冷启动检查。
- 清怪组为当幕六只混编怪，26 级起第一只使用精英生命／伤害预算；主表不抽额外精英词缀。压力对照另应用游戏真实精英词缀，并留出一秒结算死亡效果。首领使用该关实际首领，保留其 AI、克隆与召唤。
- 战斗调用实际技能、怪物、召唤、药水控制器，步长 0.04 秒。脚本约 2/3 时间攻击、1/3 时间移动，移动基准为 `3 × runSpeed`；有限跟随／绕行，不模拟真人瞬移躲技能、拆包、回城和重新召唤整支军队。
- 每场最多八瓶生命、八瓶法力药，使用该幕对应档次；保留实际回复速度、耐久、命中与抗性。每场开始前资源补满。召唤常态表假设带着已有军队，起尸和召唤费用单独记录，冷启动对照从无召唤物开始。
- 清怪 90 秒、首领 180 秒为观察上限。**超时不是零伤害，阵亡时间不是击杀时间，也不能据此断言真人无法通关。** 主表固定种子 239，地狱末期另复测 513、967；三个种子用于检查波动，不是统计胜率估计。

每一行对应数据附件中明确列出的参考加点和装备。高格挡洗点、专门能量护盾配置、减抗装备、原生技能底材与更多控场操作均可能改变结果；本轮未穷举这些优化。

开放场地省略静态地图碰撞；另用七职业的实际浏览器地图与物理系统检查施法、弹体、召唤和首领受伤。浏览器短场景与主表的走位、补给条件不同，不能直接混为同一个计时榜。

## 主要强度差异与机制风险

1. **召唤德鲁伊的前中期强度明显突出。** 36 级带军队时，真实地图中的巴尔在约 1.2 秒内被击败。乌鸦不可被攻击、固定高频出手，召唤协同又统一经过软点替换；应优先核对乌鸦协同、首击间隔和重复召唤的收益，而非只检查技能面板。相关实现：[`expansion-pets.ts`](../src/expansion-pets.ts)、[`expansion-skills.ts`](../src/expansion-skills.ts)。
2. **死灵召唤的第一具尸体与后期军队存活是瓶颈。** 骷髅军队在普通阶段能快速启动尸爆，进入地狱后若整队先被打散，尸爆再强也无从触发。眼光佣兵可帮助制造首尸，但佣兵阵亡后，后期首领续航仍可能崩溃。不能用“已有尸体时能成功施放尸爆”的功能测试代替整个循环。
3. **地狱混编怪比一些首领战更容易暴露生存问题。** 项目的高难度野外怪有独立伤害／命中增幅，而章节首领使用另一套预算；固定六怪和真实精英词缀的压力不能通过“单挑首领通过”证明安全。相关实现：[`balance.ts`](../src/balance.ts)、[`monster-affixes.ts`](../src/monster-affixes.ts)。
4. **武器流派不能只比较裸技能。** 双持武器本身、攻击速度、无法冰冻、吸取和压碎性打击会改变循环；盾击是特殊单体用途，不能按刷六怪速度解释全部价值。普通武学和成型马赛克是不同装备条件下的玩法。
5. **部分机制还不足以支持照搬原作经验。** 本项目怪物抗性统一封顶 85%，双元素绕免疫的优势较小；刃之怒的伤害路径直接附加部分武器平均伤害，没有完整经过普通武器命中结算。应先核对这些规则，再决定提高技能倍率。相关实现：[`monster-affixes.ts`](../src/monster-affixes.ts)、[`expansion-combat.ts`](../src/expansion-combat.ts)。

## 复现

基础矩阵：`npm run balance:classes`；末期多种子、装备不足、召唤冷启动、马赛克与压碎性打击对照：`npm run balance:class-variants`。两者都支持 `OUTPUT_DIR`，默认写入 `.verification/`。

基础命令可用 `AUDIT_BUILDS`、`AUDIT_STAGES`、`AUDIT_KINDS`、`AUDIT_SEEDS` 缩小范围；列表以逗号分隔。`AUDIT_MERCENARY=1`、`AUDIT_AFFIXES=1`、`AUDIT_POOR=1`、`AUDIT_MOSAIC=1`、`AUDIT_COMBAT_GEAR=1`、`AUDIT_WHITE=1` 分别启用对应对照；马赛克已有聚气组同时设置 `AUDIT_MOSAIC=1` 与 `AUDIT_CHARGED=1`。`node scripts/class-audit-recheck.mjs` 可按 `AUDIT_BUILDS` 重测指定构筑及其对照。浏览器验证：`node tests/class-audit-browser.mjs`。

工具和合法性回归见 [`class-audit-builds.mjs`](../scripts/class-audit-builds.mjs)、[`class-audit-combat.mjs`](../scripts/class-audit-combat.mjs)、[`class-audit.test.ts`](../tests/class-audit.test.ts)。完整样本、配装和施法记录见 [审计数据](data/seven-class-audit-20260915.json)。数据中的 `damage` 是直接伤害跟踪，未完整计入持续毒伤／流血，不能用作跨流派 DPS 排名；比较采用实际目标剩余生命、胜负和时间。
