# 营地本地共享仓库

更新日期：2026-09-10。

## 使用方式

罗格营地出生点前方新增“本地共享仓库”箱子。点击箱子或场景标签会自动走近并打开；靠近后也可按 F 或点击交互按钮。离开营地后不能打开或进行共享存取。

宽屏界面同时显示装备栏、个人物品、共享物品与完整详情；个人物品可切换“背包”和“个人仓库”，共享仓库为所有本地角色共用的 10 × 10 格空间。选中物品可直接装备，或使用原有存入、取回按钮；点击装备栏可卸下至共享仓库或个人仓库。手机通过上方标签切换个人、共享与装备栏，详情和操作按钮固定在下方；长内容仅在各自区域内滚动。

从共享仓库穿戴时，替换的装备放回共享仓库，不占用背包。穿戴、卸下和共享物品变化使用同一次事务保存，空间不足、存档冲突或写入失败时，不会丢失或重复物品。

个人及共享物品均可直接拖到对应装备部位穿戴；手机拖动时临时显示装备栏。共享格子内可拖动整理，完整覆盖目标区域内所有物品时交换两个区域，并保留被交换物品的相对位置；部分覆盖、越界或交换后重叠时保持原位。共享位置交换也通过数据库事务保存并通知其他窗口。

| 转移方向 | 规则 |
| --- | --- |
| 背包 → 共享仓库 | 按完整物品尺寸检查空位，成功后从角色背包移除 |
| 个人仓库 → 共享仓库 | 直接存入，不需要先腾出背包空间 |
| 共享仓库 → 背包 | 按角色背包 10 × 4 格检查空间，放不下则保持原位 |
| 共享仓库 → 个人仓库 | 直接取回，保留个人仓库现有扩展布局及 200 件存档上限 |

装备、护身符、珠宝以及背包/个人仓库中保存为物品的杂物均可转移。穿戴中的装备需要先卸下。金币、独立符文列表、药剂与箭矢储备不属于背包物品，本次不提供这些独立资源的转移。

物品的 ID、随机属性与掷值记录、孔数、符文顺序、镶嵌珠宝、耐久、投掷数量和鉴定状态保持不变，仅为目标容器重新寻找位置。共享仓库内的护身符不提供属性；从背包存入时立即重新限制生命/法力等上限。共享物品可直接装备，出售、鉴定或加工需先取回个人容器。

同一浏览器配置、同一访问地址下的本地角色共用该仓库。换浏览器、端口、域名或设备会访问另一份本地存储，不提供局域网或云端同步。删除存入物品的角色不会删除共享仓库中的物品。单角色导出只包含该角色实际持有的物品，不附带整个共享仓库；需要随角色迁移的共享物品应先取回。

## 一致性与失败处理

一次存取将“角色更新后的状态”和“共享仓库更新后的物品”作为一个数据库事务提交。成功前不修改当前页面的角色；数据库写入失败、容量不足、物品不存在或版本冲突时，保留原状态并显示错误。

不同窗口的数据库写事务会串行执行，并检查角色版本和共享仓库版本。同一件物品不能被两个窗口同时取走；已打开仓库的其他窗口收到通知后刷新。相同角色的旧页面通过角色版本及共享事务编号识别过期状态，避免自动保存把已存出的物品恢复到背包。

角色普通存档仍使用 `localStorage`。共享仓库的权威记录位于 IndexedDB 数据库 `eclipse-ii-local-shared-v1` 的 `shared` 对象仓库、`state` 记录中，包含共享物品及每个参与角色最后一次事务的恢复快照。角色读取、列表和导出会使用尚未被后续正常保存确认的快照，因此提交后即使立即关闭页面，也不依赖第二次角色写入完成转移。

`eclipse-ii-shared-stash-v1` 的 localStorage 值是兼容镜像。镜像写入失败不会撤销已经提交的数据库事务；其他窗口通过通知重新读取数据库。应使用游戏的读取接口或完整网站数据备份，不应仅复制角色旧键来推断转移后的所有权。损坏记录会报错并保留原数据，不会静默重置为空仓库。

共享容器不接受与目标已有物品 ID 冲突的重复副本，避免导入同一角色副本后在同一个容器内产生无法区分的物品。

## 验证与代码入口

- [shared-stash.ts](../src/shared-stash.ts)：存取、穿脱、位置交换、格子容量、重复 ID 与物品状态。
- [shared-storage.ts](../src/shared-storage.ts)、[saves.ts](../src/saves.ts)：数据库事务、角色恢复快照、旧窗口保护、共享更新通知。
- [shared-stash-ui.ts](../src/shared-stash-ui.ts)、[shared-stash.css](../src/shared-stash.css)：个人/共享容器及存取操作。
- [camp.ts](../src/camp.ts)、[world.ts](../src/world.ts)、[game.ts](../src/game.ts)：营地箱子、碰撞、自动接近与交互范围。

`tests/shared-stash.test.ts` 验证双向跨角色转移、随机物品保存、容量、提交失败、角色写入不可用、并发争抢、旧自动保存、损坏记录、护身符及删除原角色后的物品保留。

`npm run test:shared-stash` 验证桌面/手机营地箱子与画布、四个转移方向、满背包下私人/共享仓库直接穿脱、完整属性展示、切换角色和重载、真实数据库写入失败、双窗口争抢、镜像失败后的窗口通知和属性保留。可通过 `BASE_URL` 指定服务地址，截图输出到 `.verification`。

`npm run test:inventory-drag` 验证鼠标、触屏及键盘移动，完整区域交换、半件覆盖拒绝、取消、双手装备替换、满背包仓库换装，以及共享拖拽写入失败后的回滚和重载。
